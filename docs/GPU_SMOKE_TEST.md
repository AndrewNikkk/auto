# Проверка на RTX 3090/4090

Текущий результат разработки: **REQUIRES GPU VERIFICATION**. CPU, API mocks и FFmpeg не подтверждают inference.

После успешного `./setup.sh` выполните на GPU-сервере:

```bash
./gpu-smoke-test.sh
```

Скрипт проверяет GPU внутри одного app-контейнера и hashes весов, затем запускает полный реальный 30-секундный target RU+EN what-if. Изображения общие, WAV/субтитры/рендеры разные. Никаких mock adapters в smoke нет. Проверяющий модуль требует:

1. Успешную Ollama генерацию отдельных сценариев обоих языков.
2. Восемь валидных PNG ComfyUI 832×1216.
3. Валидные независимые RU и EN WAV с восемью сегментами.
4. Word alignment обоих языков без fallback.
5. H.264/AAC 1080×1920, 30 FPS MP4 нужной длительности.
6. Доступный NVML, GPU name, peak memory и возврат памяти после каждой тяжёлой стадии.
7. Реальные длительности этапов в generation_report.json.

Успех заканчивается `VERIFIED: GPU end-to-end smoke test`. При ошибке код возврата ненулевой; проверьте `generation_report.json` и `.gpu-procs/*.log`. Наличие UI или прохождение unit tests не заменяет smoke.

Скопируйте результаты (ID печатается в конце):

```bash
docker compose cp app:/data/outputs/YOUR_RUN_ID ./gpu-smoke-result
```

Просмотрите оба видео: хук/факты, качество русского и английского Ryan, отсутствие обрезанных центральных объектов, плавность переходов и синхронизацию подсветки. Оцените качество на реальных сценах, не только на тестовом коротком WAV. Убедитесь, что после прерывания CLI/Ctrl-C и остановки контейнера не остаются дочерние GPU-процессы. Проект не завершает чужие процессы.

Для замера целевого 45-секундного ролика, после загрузки весов:

```bash
docker compose exec app python -m app.generate \
  --prompt "Почему лёд плавает?" --languages ru --duration 45 --type science
```

Читайте `total_s`, `timings`, `per_language`, `stages.*.peak_vram_bytes`, `memory_released`. Цель ≤900 s относится к одному языку на RTX 3090 и пока не измерена. Не называйте длительность CPU fixtures benchmark генерации. Длительность готового видео равна реальной речи, 45 s — целевой бюджет текста.

Проверка итоговой громкости (после копирования файла, FFmpeg на хосте):

```bash
ffmpeg -hide_banner -i gpu-smoke-result/video_ru.mp4 -af loudnorm=I=-14:TP=-1:LRA=11:print_format=json -f null -
```

`input_i`/`input_tp` — измерения готового AAC. Зафиксируйте отклонение от -14 LUFS и true peak ≤-1 dBTP. Двухпроходная обработка присутствует, но точные метрики конечного AAC на GPU-материале ещё не проверены.

Рекомендуемая матрица при первом развёртывании: ru, en, ru,en; 30/45/60 s; news с реальным текстом; музыка loop/trim/fade; испорченный PNG и resume; OOM, timeout и SIGTERM. Для этих сценариев unit/mock tests существуют, но реалистичное поведение моделей требует сервера.
